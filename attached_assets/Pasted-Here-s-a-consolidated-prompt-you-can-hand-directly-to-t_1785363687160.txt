Infraspective UI/UX & Beta Release Refinement

Objective

Refine the application’s UI/UX to achieve a polished, professional engineering aesthetic suitable for a commercial beta release. The objective is not to redesign the application, but to improve consistency, visual hierarchy, usability, and legal compliance while preserving the existing engineering workflow.

⸻

1. Landing / User Agreement Screen

Logo Integration

The logo itself looks correct.

However, the presentation does not.

Current issue:

* The logo appears as if it was simply placed inside a white rectangle.
* It does not visually blend into the application.

Update the logo container so that it integrates naturally into whatever background is being used.

Possible improvements include:

* subtle glass effect
* translucent panel
* frosted appearance
* soft gradients
* reduced hard borders
* softer shadows
* background blending

The logo should feel like it belongs to the application rather than sitting on top of it.

Do not modify the logo artwork.

Only redesign how it is displayed.

2. User Agreement

Keep the agreement concise, professional and legally clear.

⸻

Beta Software

State that:

* This application is Beta software.
* It may contain bugs.
* It may contain errors.
* Features may be incomplete.
* Calculations may contain inaccuracies.

⸻

Professional Verification

Replace Alberta-specific wording.

Do not reference:

* APEGA
* PEO
* EGBC
* Engineers and Geoscientists Alberta
* Engineering and Geoscience Professions Act

Instead state generally:

This software is a calculation aid only.

It does not replace professional engineering judgement.

All outputs must be independently verified by a licensed Professional Engineer in Canada before being relied upon for project use.

Stress clearly:

* manual verification is mandatory
* user assumes responsibility for verification
* outputs are not to be relied upon directly

⸻

Data Usage

Do not say users are required to provide technical feedback.

Instead state that by using the application the user grants permission for Infraspective to collect anonymous application usage information, interaction patterns and technical input parameters for:

* improving calculations
* improving software performance
* fixing bugs
* improving usability

No requirement to submit written feedback.

⸻

Limitation of Liability

Keep this section.

Emphasize:

* Beta software
* bugs
* incomplete functionality
* user assumes risk
* independent verification required

⸻

Indemnity

Current wording is acceptable.

⸻

Governing Law

Do not hardcode Alberta.

Instead use wording similar to:

This Agreement shall be governed by the applicable laws of Canada together with the applicable laws of the jurisdiction in which the User resides or uses the software where legally required.

Avoid making the agreement Alberta-only.

⸻

Severability

Current wording is acceptable.

⸻

Verification Acknowledgement

Keep.
